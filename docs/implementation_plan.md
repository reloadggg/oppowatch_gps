# KartLap-SE 项目实施计划

## 1. 项目概览
- **目标设备**：OPPO Watch SE（Wear OS）。
- **核心目标**：实现离线圈速记录应用，满足稳定定位、轨迹绘制与数据导出需求。
- **约束原则**：仅使用标准 Android API；支持熄屏与无网络场景；保证后台稳定性与数据完整性；界面需符合手表交互习惯。

## 2. 里程碑划分
| 阶段 | 时间 | 目标 | 关键输出 |
| --- | --- | --- | --- |
| M1. 基础框架搭建 | 第 1 周 | 完成前台服务、WakeLock、权限引导等核心后台能力。 | T1, T2, T3 |
| M2. 稳定性增强 | 第 2 周 | 增加心跳自恢复、运动唤醒策略、数据写入可靠性。 | T4, T5, T6 |

## 3. 任务拆解与依赖
### 阶段 M1：后台基础能力
1. **T1 前台服务持续定位**  
   - 创建 `RecordService` 作为 ForegroundService，配置 CATEGORY_WORKOUT 通知。  
   - 集成 LocationManager，确保熄屏后仍能获取定位回调。
2. **T2 CPU 唤醒保持**  
   - 新建 `WakeLockManager`，在服务启动时申请 PARTIAL_WAKE_LOCK，定时续期。  
   - 在 `onDestroy()` 中确保释放。
3. **T3 电池优化豁免**  
   - `BatteryOptimizationHelper` 检测优化状态并引导用户授权，结合 `battery_prompt` 布局展示步骤。  
   - 针对 ColorOS 提供快捷跳转。

**依赖**：T1 依赖 T2 确保后台；T3 提前完成以指导用户授权。

### 阶段 M2：稳定性增强
4. **T4 心跳与服务自恢复**  
   - `AlarmManagerHelper` 配置 10 分钟心跳，`HeartbeatReceiver` 检测定位流状态。  
   - 服务使用 `START_STICKY`，在心跳中重新启动服务。
5. **T5 运动传感器唤醒**  
   - `MotionSensorManager` 注册加速度计与陀螺仪，运动时刷新 GPS 请求，静止时降频。
6. **T6 GPS 数据原子写入**  
   - 设计 `AtomicFileUtils` 封装 AtomicFile；`TrackWriter` 支持周期 flush 与文件安全替换。

**依赖**：T4 基于 T1 服务框架；T5 需要 T1 的定位逻辑；T6 与后续数据管理相关。

### 阶段 M3：数据管理与导出
7. **T7 断点续写与日志完整性**  
   - `TrackSessionManager` 负责会话状态机、未完成会话恢复、EOF/校验标记管理。
8. **T8 数据导出**  
   - `ExportManager` 调用 `GPXExporter` 与 `CSVExporter`，支持日期+会话编号命名。  
   - 结合 `AtomicFileUtils` 实现导出原子写入。
9. **T10 稳定性测试**  
   - 制定测试脚本（熄屏 30 分钟、杀进程等），记录丢失率和恢复时延，输出报告。

**依赖**：T7 需要 T6 的原子写入基础；T8 在 T7 会话管理完成后进行；T10 在所有功能完成后执行。

### 阶段 M4：界面与交互
10. **UI1 主界面**  
    - `MainActivity` 与 `activity_main.xml` 提供开始/结束/保存流程，统计信息展示。  
    - `strings.xml` 补充国际化文案。
11. **UI2 实时轨迹绘制**  
    - `TrackView` + `PathProjector` 实现轨迹投影、自动缩放与高亮。  
    - 与 `RecordService` 数据流对接。
12. **UI3 设置页（可选）**  
    - `SettingsActivity` 与 `prefs.xml` 提供采样、阈值等配置项，使用 SharedPreferences 持久化。

**依赖**：UI 组件需在后台服务与数据管理完成后联调；UI2 依赖 T6/T7 的实时数据缓冲；UI3 在核心功能稳定后实现。

## 4. 技术要点与设计原则
- **定位策略**：优先使用 `LocationManager.GPS_PROVIDER`，在后台维持高精度更新；在无活动时降低频率以节能。
- **资源管理**：统一封装 WakeLock、传感器、AlarmManager，避免资源泄漏。
- **数据安全**：通过 AtomicFile + checksum 确保轨迹文件可靠；导出路径使用应用私有存储，用户可通过共享方式导出。
- **UI Design & Interaction**：布局采用约束布局或 FrameLayout，按钮区域大于 48dp；提供震动反馈提升可用性。

## 5. 风险与缓解
| 风险 | 影响 | 缓解措施 |
| --- | --- | --- |
| 熄屏后定位被系统限制 | 记录中断 | ForegroundService + WakeLock + 心跳恢复，提醒用户完成电池优化豁免。 |
| 数据写入中断导致文件损坏 | 导出失败 | 使用 AtomicFile、定期 flush、会话校验标记。 |
| 传感器持续工作耗电 | 电量快速下降 | 动态注册/注销传感器，运动时提升频率，静止时降低频率。 |
| 不同厂商后台策略差异 | 后台被杀 | 设置向导提供针对性提示，心跳机制辅助恢复。 |

## 6. 测试计划
- **单元测试**：针对会话管理、导出格式转换等核心逻辑编写单元测试。
- **集成测试**：模拟服务启动/停止、心跳恢复流程，验证数据写入与恢复路径。
- **场景测试**：执行 T10 中列出的稳定性测试，记录指标并生成 `docs/stability_test_report.md`。
- **用户体验测试**：在实际手表设备上验证 UI 操作、轨迹渲染流畅度、震动反馈。
